# 从零开始创建新角色

本指南说明如何为 AIpartner 创建一个可用的新角色。角色资源全部放在项目的 `characters` 文件夹中；程序会在启动时扫描角色，因此添加或修改角色后需要重启程序。

最快的创建方法：

1. 在 `characters` 下新建一个以角色名称命名的文件夹，例如 `Ennis`。
2. 在其中创建非空的 `character_setting.txt`。
3. 重启项目，在角色选择页打开新角色。
4. 再根据需要补充配置、头像、立绘、参考语音和背景故事。

只有 `character_setting.txt` 是角色进行文本对话的必需文件。缺少头像、立绘或参考语音时，角色仍可进行文本对话，但相应的界面和语音功能不可用。

如果想要和角色进行语音聊天、并且随着聊天内容展示不同立绘，那么就需要配置角色立绘和参考语音。

创建一个有良好视觉和语音交互体验的AI伙伴可能会消耗2h+的时间。

## 0. 角色配置文件和资源简介

### 最低可用目录

```text
characters/
├─ character_config.default.toml
└─ Ennis/
   └─ character_setting.txt
```

比如针对《灵魂潮汐》中的角色“艾妮斯”，在创建角色文件夹`Ennis`（艾妮斯的英文名称，角色文件夹推荐使用角色英文名称或者拼音，避免代码中路径报错的可能性）、并撰写完成`character_setting.txt`后，就可以直接以文本格式与角色对话了（类似于微信聊天）。角色会记住你们的对话内容。

### 完整目录示例

```text
characters/
├─ character_config.default.toml
└─ Ennis/
   ├─ frontend_imgs/
   │  ├─ background_image_gal.png
   │  └─ user_profile.png
   ├─ backstory/
   │  ├─ 01_核心历程.txt
   │  ├─ 02_补充经历.txt
   │  ├─ 03_人物印象.txt
   │  ├─ 04_事物认知.txt
   │  └─ 05_角色简述.txt
   ├─ portraits/
   │  ├─ default.png
   │  ├─ happy.png
   │  ├─ sad.png
   │  └─ description.txt
   ├─ ref_audios/
   │  ├─ default.wav
   │  ├─ default.txt
   │  ├─ positive.wav
   │  ├─ positive.txt
   │  └─ description.txt
   ├─ character_config.toml
   ├─ character_setting.txt
   ├─ character_setting_summary.txt
   └─ profile.png
```

运行或导入背景故事后，系统还会自动创建：

```text
memory_db/           # realtime 模式的记忆
memory_db_sandbox/   # sandbox 模式的记忆
```

<u>**创建新角色时不要复制其他角色的这两个记忆文件夹，否则会一并复制对方的对话记录和记忆。**</u>

### 文件用途与重要程度

| 文件或目录 | 重要程度 | 作用 |
|---|---|---|
| `character_setting.txt` | **必须** | 完整角色设定，决定角色如何理解自己和回应用户。 |
| `character_config.toml` | 推荐 | 覆盖角色显示名称、场景模式、主题和记忆参数。 |
| `profile.png/jpg/jpeg` | 推荐 | 角色选择页和文本对话界面使用的头像。 |
| `portraits/` | 推荐 | 演出模式使用的角色立绘。 |
| `ref_audios/` | 推荐 | Qwen3-TTS 进行语音克隆时使用的参考语音和文本。 |
| `backstory/` | 推荐 | 可导入 ChromaDB 的结构化角色经历、人物关系和事物认知。 |
| `character_setting_summary.txt` | 自动生成 | 角色设定摘要；缺失或过期时由大模型重新生成。 |
| `frontend_imgs/` | 可选 | 角色专属聊天背景和用户头像。未配置时使用全局默认资源。 |
| `memory_db*` | 自动生成 | 对话历史、近期记忆、长期记忆和 ChromaDB 数据。 |

### 角色文件夹命名

角色文件夹名同时是程序内部的角色 ID。建议使用简短的英文名或拼音，例如：

```text
Elysia
Ennis
Colcher
```

建议只使用英文字母、数字、短横线和下划线，避免使用路径符号或过长名称。对外显示的中文名可以在 `character_config.toml` 中通过 `[character]` 下的 `true_character_name` 设置。

## 1. 角色设定文档（必须）

文件位置：

```text
characters/角色文件夹名/character_setting.txt
```

要求：

- 文件名必须为`character_setting.txt`。
- 使用 UTF-8 编码保存。
- 内容不能为空。
- 优先描述稳定、会影响对话的设定，不必堆积与当前交流无关的世界观资料。
- 明确角色如何看待 User，以及两者的初始关系。
- **不要在设定中写入大模型 API Key，不建议写入其他真实个人隐私等敏感信息。**

### 建议格式

```text
### 基本设定
姓名：中文名称（英文名称）
身份：角色的身份、职业、种族或所属组织
简述：角色的核心定位、性格，以及与 User 的关系

### 角色详细设定
【背景故事】
概括出身、主要成长阶段、关键转折、重要关系变化，以及这些经历如何塑造角色当前的目标。

建议不超过 400 个汉字。

【性格特质】
世界观与价值观：
对待他人的基本态度：
主要愿望、恐惧与执念：
喜欢、讨厌或无法接受的事物：
自我评价：

建议不超过 300 个汉字。

【语言与行为风格】
对话风格：
常用称呼或口癖：
面对亲近者、陌生人、敌人或压力时的典型反应：
可供模仿的代表性表达：

建议不超过 300 个汉字。

### User 的身份
说明 User 扮演的身份、与角色的初始关系，以及角色通常如何看待和称呼 User。

### 回复要求
说明希望角色遵守的回复长度、叙事视角、动作描写方式等。没有特殊要求时可以省略。
```

### 角色设定摘要

`character_setting_summary.txt` 无需手动创建。第一次初始化角色时，如果该文件不存在、内容为空，或者旧于 `character_setting.txt`，系统会调用大模型重新生成并保存摘要。

<u>如果已经通过第 3 部分生成了 `05_角色简述.txt`，可以将其中适合长期指导角色扮演的内容整理到 `character_setting.txt` 中。</u>

## 2. 角色配置文件（推荐）

所有可配置项和说明都可以在 `characters/character_config.default.toml` 中查看。

角色配置文件位置：

```text
characters/角色文件夹名/character_config.toml
```

角色配置会覆盖 `characters/character_config.default.toml` 中的同名项目。没有特殊需求时只写需要修改的项目，不要复制整份默认配置。

推荐的最小配置：

```toml
[character]
# 对外显示名称；留空时使用角色文件夹名。
true_character_name = "艾妮斯"
# realtime 或 sandbox。
scene_mode = "sandbox"

[translate]
# 语音输出的目标语言；留空表示不翻译。
target_language = ""
```

### 场景模式

```toml
[character]
scene_mode = "sandbox"
```

- `realtime`：角色可以感知现实时间；配置搜索 API 后可以使用网络搜索。记忆保存在 `memory_db`。
- `sandbox`：适合架空世界或角色扮演，不依赖现实时间，也不启用网络搜索。记忆保存在 `memory_db_sandbox`。

两个模式的记忆完全独立。切换模式不会迁移原有记忆，切回原模式后仍可继续使用原来的记忆库。

### 语音翻译设置

当你想使用中文与角色对话，但是参考语音是日语（或其他语言）时，如果直接合成中文语音，那么会带有极其严重的日语口音。此时推荐设置`target_language`参数，系统会将中文翻译为日语后再进行语音合成。这样，你和角色的交流效果就类似于玩二游过剧情时，使用中文文本，但是同时使用日语配音。

默认配置如下，不需要翻译时可以完全省略这一部分：

```toml
[translate]
# 角色回复正文的语言，默认为中文。
source_language = "Chinese"
# 语音输出的目标语言；留空表示不翻译。
target_language = ""
```

如果希望“中文对话文本 + 日语配音”，在角色的 `character_config.toml` 中添加：

```toml
[translate]
target_language = "日语"
```

或者：

```toml
[translate]
target_language = "Japanese"
```

`source_language`和`target_language`两个字段均支持表格内的中文名称或对应的英文名称：

| 中文名称 | 标准英文名称 |
|---|---|
| 中文 | `Chinese` |
| 英语 | `English` |
| 德语 | `German` |
| 意大利语 | `Italian` |
| 葡萄牙语 | `Portuguese` |
| 西班牙语 | `Spanish` |
| 日语 | `Japanese` |
| 韩语 | `Korean` |
| 法语 | `French` |
| 俄语 | `Russian` |

注意：

- `source_language` 指你会看到的对话框中的语言，不是参考音频语言，也不会改变聊天模型的回复语言。只有送入 TTS 的台词会被翻译，界面、聊天历史和记忆仍保留原文。**如果你使用中文和AI伙伴对话，那么`source_language`不需要改动。**
- 参考音频对应的 TXT 必须继续记录音频中实际说出的文字。例如日语参考音频仍配日语参考文本，不要将其替换为中文译文。
- 修改后需重新初始化角色才能生效。

#### 角色翻译指导

可选内容。启用语音翻译后，可以在角色目录下添加 `translation_guide.txt`（与 `character_setting.txt` 同级），用几条简短规则说明译文的称呼、口癖和说话习惯。它只影响送入 TTS 的译文，不改变界面显示的正文。例如日语翻译指导可以写为：

```text
将“前辈”译为“先輩”，自称使用“私”。
语气活泼亲切，保留原文撒娇或调侃的感觉。
```

**建议保持简短，以免增加翻译带来的对话延迟。**

指导内容只在角色初始化时读取，修改后需重新初始化角色才能生效。

### 图片识别

默认配置已经开启图片入口。如需在某个角色的 `character_config.toml` 中单独开启或关闭，可以添加：

```toml
[vision]
vision = true  # 改为 false 可关闭该角色的图片入口
```

目前支持 JPG、JPEG 和 PNG，一次最多 3 张、单张最多 10 MiB，也可以只发送图片。

项目根目录的 `.env` 还需要同时配置 `LLM_VISION_API_KEY`、`LLM_VISION_MODEL_ID` 和 `LLM_VISION_BASE_URL`，所选视觉模型必须支持图片输入及工具调用。配置不完整时，图片入口不可用，但仍可正常进行纯文字聊天。

只有本次携带图片时才会调用视觉模型，后续追问图片中未被识别描述保留的细节时，需要重新上传图片。

### 演出工具设置

如需覆盖默认配置，可以添加：

```toml
[display]
tool_call_content_allowlist = ["web_search_tool", "search_memory_tool"]
```

该列表决定哪些工具调用产生的角色文本可以进入旮旯演出模式的演出队列，即会对该工具调用过程中产生的附加对话分配立绘并进行语音合成。**一般情况下保持默认即可。**

目前有效工具名只有：

- `web_search_tool`
- `search_memory_tool`

### 记忆参数

记忆参数已有合理默认值。**一般情况下保持默认即可。**

TOML 字符串必须使用引号，布尔值必须写成小写 `true` 或 `false`。格式错误会导致角色初始化失败。

## 3. 角色背景故事（推荐）

背景故事用于补充角色的详细经历、人物关系和事物认知。**<u>它不会自动进入数据库，完成文件后还需要执行一次导入命令。</u>**

不建议手工从大量资料中逐条整理。可以使用同目录下的提示词交给 Agent 应用完成（比如Codex、Claude Code，国内的WorkBuddy、百度搭子等)：

- 有可靠网页资料时：`角色总结提示词-网络搜索版.md`
- 已有小说、设定集、剧本或其他本地资料时：`角色总结提示词-文件优先版.md`

> 使用提示词前，请先修改提示词开头的角色名称。

Agent完成后，建议检查输出的内容，并根据自己的需要进行修改，但是字数和格式要满足相应要求。

### 正式导入文件

导入器只读取以下四个文件，而且四个文件必须同时存在：

```text
01_核心历程.txt
02_补充经历.txt
03_人物印象.txt
04_事物认知.txt
```

`05_角色简述.txt` 用于辅助撰写角色设定，不会被背景故事导入器读取。工作清单等其他文件也不会被导入。

<u>请将以上文件内容放在角色`backstory`文件夹下。</u>

### 记录格式

四类记录的第一行必须分别以这些标题开头：

| 文件 | 第一行必须以此开头 |
|---|---|
| `01_核心历程.txt` | `【事件】` |
| `02_补充经历.txt` | `【经历】` |
| `03_人物印象.txt` | `【对象】` |
| `04_事物认知.txt` | `【对象】` |

每条记录末尾必须单独写一行：

```text
<<<RECORD_END>>>
```

示例：

```text
【事件】第一次与 User 相遇
【时间】故事开始前一年
【关键词】初遇｜误会｜共同任务
【内容】说明事件经过，保证这条记录脱离其他上下文后仍可独立理解。
【影响】说明该事件如何影响角色的性格、关系或后续选择。
<<<RECORD_END>>>
```

单条记录不能超过 500 个字符，建议控制在 300 个字符以内。所有文件使用 UTF-8 编码。

### 导入背景故事

导入前必须先关闭正在运行的聊天程序。

在已配置 Conda 的终端中，进入项目根目录（包含 `import_backstory.py` 的目录）

```powershell
cd "yourPath\AIpartner"
```

激活当前使用的 `aipartner` 环境后执行：

```powershell
conda activate aipartner
python import_backstory.py Ennis --scene-mode realtime
```

将 `Ennis` 替换为角色文件夹名。沙盒模式在同一环境和目录下执行：

```powershell
python import_backstory.py Ennis --scene-mode sandbox
```

导入器会先完整检查四个文件。任何记录格式错误时都不会写入数据库；成功导入时，会**全量替换**（即删除之前所有的背景故事，并写入新的背景故事）该模式下这个角色原有的背景故事记录，但不会删除正常对话产生的记忆。

## 4. 角色头像（推荐）

头像直接放在角色根目录，文件名必须为 `profile`：

```text
profile.png
profile.jpg
profile.jpeg
```

支持 PNG、JPG 和 JPEG。建议只保留一个头像；如果同时存在多个，程序会按 PNG、JPG、JPEG 的顺序选择。

建议：

- 使用正方形图片。
- 保证主体在缩略图中清晰可见。
- 避免把重要内容放在图片边缘。
- 不配置头像不会影响文本对话，只会使用无头像样式。

## 5. 角色立绘（推荐）

立绘放在：

```text
characters/角色文件夹名/portraits/
```

支持 `.png`、`.jpg` 和 `.jpeg`。可以按情绪或动作命名，例如：

```text
default.png
happy.png
sad.png
angry.png
confused.png
```

默认立绘优先使用：

1. `default.*`
2. `角色文件夹名_default.*`
3. 都不存在时，使用扫描到的第一张立绘并输出警告

建议始终提供 `default` 立绘。

### 立绘说明文件

在 `portraits/description.txt` 中，每行使用“完整文件名 + 冒号 + 使用场景”：

```text
default.png: 用于普通交流和没有明显情绪时。
happy.png: 用于收到好消息、被称赞或心情愉快时。
sad.png: 用于失落、告别或谈到遗憾时。
angry.png: 用于遭遇冒犯、不公或激烈冲突时。
```

中英文冒号均可。文件名必须包含扩展名，并与实际资源完全对应。空行会被忽略。

程序初始化角色时会生成 `description_rectified.txt`，用于展示规范化结果和发现拼写错误。请编辑原始的 `description.txt`，不要把 `description_rectified.txt` 当作配置源。

**如果 `portraits` 缺失或没有有效图片，角色会自动退化为文本模式，仍可进行文本对话。**

## 6. 参考语音（推荐）

参考语音放在：

```text
characters/角色文件夹名/ref_audios/
```

支持 WAV 和 MP3。每个音频必须有一个同名的 TXT 文件，内容是该音频中实际说出的文字：

```text
default.wav
default.txt

happy.wav
happy.txt
```

`default.txt` 示例：

```text
你好呀，今天也要一起度过一段愉快的时光吗？
```

缺少同名 TXT、TXT 内容为空或音频无法读取时，该条语音会被忽略。建议始终提供 `default.wav` 和 `default.txt`。

参考语音建议：

- 使用单人、清晰、无背景音乐的音频。
- **文本必须与实际语音一致。**
- 避免明显混响、爆音和长时间静音。
- 不同情绪的音频使用不同文件名，例如 `happy`、`sad`、`angry`。
- 请注意声音素材的版权问题。
- 存在多个参考语音时，请选取音色尽可能一致的语音片段。
- 同一个语音片段内的语气不要有太大变化。
- **参考语音并不是越多越好！一个长度在6-12秒的优质角色语音就能达到较好的对话效果。**

### 语音说明文件

`ref_audios/description.txt` 格式与立绘说明相同：

```text
default.wav: 用于普通交流和没有明显情绪时。
happy.wav: 用于开心、庆祝或表达期待时。
sad.wav: 用于低落、遗憾或安慰他人时。
```

程序同样会生成 `description_rectified.txt` 供检查。

**语音生成还要求本机能够使用 CUDA，并成功加载 Qwen3-TTS。GPU、模型或参考语音不可用时，角色会自动退化为文本模式，仍可进行文本对话。**

## 7. 前端其他资源（可选）

这些都可以在聊天界面中上传和替换。未配置时，程序会使用 `frontend/imgs` 中的全局默认资源。

角色专属前端图片放在：

```text
characters/角色文件夹名/frontend_imgs/
```

目前支持两种资源：

```text
background_image_gal.png  # 演出模式背景
user_profile.png          # 与该角色聊天时显示的 User 头像
```

也支持 JPG 和 JPEG，但文件主名必须是 `background_image_gal` 或 `user_profile`。单张图片不能超过 15 MB。

## 8. 记忆文件夹（无需手动配置）

角色第一次初始化或导入背景故事时，系统会自动创建对应的记忆目录：

```text
memory_db/           # realtime
memory_db_sandbox/   # sandbox
```

其中包含：

- ChromaDB 向量数据库；
- 对话历史；
- 近期记忆；
- 长期核心传记；
- 数据库索引文件。

注意：

- **不要手工创建或编辑其中的数据库文件。**
- **不要在程序运行时复制、移动或覆盖记忆目录。**
- **备份角色时，应在关闭程序后复制整个角色文件夹。**
- **想创建没有任何对话的新角色时，不要复制其他角色的 `memory_db` 或 `memory_db_sandbox`。**
- **删除记忆目录会永久清除对应场景模式的对话和记忆，操作前应先备份。**

## 完成后检查

创建完成后，按以下顺序检查是否有错误：

1. 角色文件夹位于 `characters` 的直接下一层。
2. `character_setting.txt` 存在、非空并使用 UTF-8 编码。
3. `character_config.toml` 是有效 TOML，`[character]` 下的 `scene_mode` 只能是 `realtime` 或 `sandbox`。
4. 头像文件主名是 `profile`。
5. 至少准备一张 `default` 立绘，或接受退化为纯文本模式，无法进行立绘和语音交互。
6. 每个参考音频都有同名 TXT，或接受退化为纯文本模式，无法进行立绘和语音交互。
7. `description.txt` 中写的是完整文件名，包括扩展名。
8. 新角色没有复制任何旧角色的记忆目录 `memory_db/memory_db_sandbox`。
9. 重启项目，再到角色选择页打开该角色。

如果角色能出现在选择页，但打开时失败，优先查看运行窗口中的错误信息。最常见原因是角色设定为空、TOML 格式错误、缺少立绘/语音默认资源，或参考音频没有同名文本。
